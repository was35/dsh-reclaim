# ADR 0001: 作为 @michengai/dsh-archive-manager 的伴生扩展插件

## 状态

已决定 (Decided) — 2026-11-04

## 上下文与问题背景

1. **上游盲区**：`@michengai/dsh-archive-manager` 是 DSH 生态中成熟的会话归档与管理插件，负责会话的归档、恢复、收藏以及会话本体的物理删除（`deleteSession`）。但受限于 DSH 官方附件池的无引用计数机制，上游在删除会话转录（`session.jsonl`）时**完全不清理附件（`~/.dsh/attachments/`）与派生缩略图**。大量图片附件在会话被删后沦为“孤儿文件（Orphan Files）”，永久占用磁盘。
2. **历史冲突（Issue #14）**：此前 `dsh-reclaim` 独立提供会话删除功能（`lib/delete-session.js`），但删除已归档会话后，因未修改上游插件的全局记账 `archivedSessionIds`，导致上游插件持续报告该会话读取损坏。
3. **用户核心诉求**：
   - 正常会话归档、恢复、删除完全由 `@michengai/dsh-archive-manager` 统一管理；
   - 上游未能触及到的附件文件、缓存、孤儿产物的审计、安全隔离与彻底删除，由 `dsh-reclaim` 管理；
   - 上游插件必须能**完全跟随官方更新**，下游不做任何侵入式修改或代码 Fork；
   - `dsh-reclaim` 移除与上游冲突的会话本体删除功能，转型为下水管道工与深层存储安全网；
   - 双方功能在前端界面形成协同联动。

## 架构决策

1. **伴生扩展插件模式（Companion Extension）**
   - 两个插件在 DSH profile 中作为同级 bundle 安装。
   - `dsh-archive-manager` 保持官方原版，不打任何补丁。
   - `dsh-reclaim` 作为其伴生插件，承接其生命周期下游的产物治理。

2. **职责边界与冲突剥离**
   - **会话业务生命周期（归档/解档/删除会话文件）**：100% 归 `@michengai/dsh-archive-manager`。
   - **深层存储治理（孤儿附件/派生缓存/隔离恢复/彻底粉碎）**：100% 归 `dsh-reclaim`。
   - **功能下线**：`dsh-reclaim` 剥离自身对活会话/归档会话本体的直接物理删除能力（停用 `lib/delete-session.js` 的会话删除动作），彻底消除 #14 式跨插件记账不一致的根源。

3. **事件级协同（Event-Driven Lifecycle）**
   - 监听 `dsh-archive-manager` 在删除会话时广播的 Cordis 事件 `api-session/removed`。
   - 捕获到会话删除后，`dsh-reclaim` 触发引用图谱（`lib/graph.js`）的差量失效与孤儿检测，将曾经被该会话独占引用的附件安全纳入可回收清单。

4. **安全哲学与隔离区保证**
   - 继承并坚守 `dsh-reclaim` 的核心安全原则：绝不直接 `rm`，优先移入可逆隔离区（Quarantine/Trash），支持一键无损还原，二次确认才彻底销毁（Purge）。

5. **界面协同**
   - 保留独立的「设置 → 空间回收」作为深层治理中枢，重新组织面板卡片（聚焦于“孤儿附件与产物”和“可重建缓存”）。
   - 在前端轻量监听删除事件，提供非侵入式的“会话已删除，发现关联附件残留，可一键移入隔离区”的交互提示。

## 影响与后果

- **正面**：
  - 彻底解决了会话删除后附件永久泄露的行业顽疾；
  - 彻底根治了 Issue #14 描述的会话删除跨插件状态悬挂；
  - 上游插件可自由升级，无需维护 Fork 分支；
  - 用户获得了会话产物“可逆找回（Quarantine）”的安全网。
- **负面 / 权衡**：
  - `dsh-reclaim` 需重组前端设置面板，并下线原有的会话复选卡片；
  - 孤儿附件判定依赖全局引用图谱的完整性（`referencesProvenComplete`），若存在未读日志，附件孤儿判定仍会按安全规则保守暂停。
